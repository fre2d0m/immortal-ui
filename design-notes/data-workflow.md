# 数据处理工作流

`data-workflow` 是面向生态环境 IoT 的可安装 Block，使用 React Flow 12。它让操作者编排事件、多源输入、数据处理、并行分支、汇合与结果分发，检查配置，并追溯一次执行的逐节点输入输出。

入口：`#/blocks/data-workflow`，分类：Blocks → 数据处理。源码是 `registry/immortal/blocks/data-workflow.tsx`；类型与结构校验在同目录 `workflow-model.ts`，局部样式在 `data-workflow.css`。演示模板、观测和执行器分别位于 `src/lib/workflow-demo-data.ts`、`src/lib/workflow-demo-runner.ts`，不属于安装依赖。

## 界面与能力

| 区域 | 用途 |
| --- | --- |
| 就近选节点 | 空画布显示虚线触发节点。未连接的输出端伸出短线与加号；已有连线在中间提供一个插入入口。点击或拖线到空白处即在附近选择兼容节点。宿主传入能力模板，展示层提供 18 个示例模板。 |
| 工作区 | 独立布局，不套用 Panel。画布常驻，选择器跟随操作位置，选中节点才显示配置。支持拖动、连接、缩放、全图、缩略图、展开工作区和节点定位。节点端口朝向依据实际连接和节点位置调整；布局不表示物理位置或耗时。 |
| 节点配置 | 名称、参数、数据类型、超时、最多尝试次数和汇合策略。凭据使用宿主连接引用，组件不读取密钥。 |
| 连接编辑 | 端点选择器支持新增和连接已有节点；可用键盘和触控完成。选中连线后可通过两端圆形手柄拖动重接；侧栏提供明确的“来源与输出”和“目标节点”选择，并可定位两端、插入步骤或删除。 |
| 右键菜单 | 画布提供触发器、历史与视图操作；节点提供配置、执行数据、复制与移除；连线提供编辑、插入、定位与移除。动作随只读、运行状态及实际回执调整。键盘聚焦对象后可用 Shift+F10 打开。 |
| 编辑历史 | 最多 50 个本地撤销步骤，支持按钮与 Ctrl/⌘ Z、Shift Ctrl/⌘ Z；连续输入合并，单次拖动作为一个步骤。外部替换定义后清空本地历史，防止撤销覆盖宿主的新版本。复制节点不复制连线。 |
| 结构校验 | 检查必填参数、重复标识、缺少入口/出口、孤立节点、循环、重复连接和声明的数据类型。问题阻止测试，但允许保存未完成草稿。 |
| 运行结果 | 底部折叠条显示本次状态和实际总耗时；展开后左侧定位节点记录，右侧就地核对输入、输出、异常与执行信息。失败优先展示，可筛选失败节点；主动选择后不被进度更新切走。开始/结束时间、运行标识在运行详情中核查，不补造吞吐量或业务结论。 |
| 导入与导出 | JSON 保存配置和布局；导入先验证形状，再允许修复结构问题。2 MB、500 节点与 2000 条边是导入保护上限，不是已验证的性能承诺。 |

内置界面统一使用英文，包括标题、节点类型、操作菜单、表单、状态、错误和运行结果。演示模板及说明同样使用英文；旧版内置草稿的已知名称与字段标签在读取时迁移，保留自定义名称、参数值、标识和拓扑。宿主传入的业务文案按原值展示。

## 组件与宿主的分工

`workflow` / `onChange` 是受控编辑接口。没有 `onChange` 时只读。`templates` 是调用方的节点能力目录，`operation` 是应用适配器的标识，组件不执行代码字符串。数据类型是调用方声明的契约；`any` 明确放宽连线检查，不意味着实际数据必然兼容。

头部与画布工具栏使用图标按钮。画布内仅保留撤销/重做与视图控制，添加步骤直接从未连接输出或连线中间进入；无需打开左侧节点库或大纲。动作提示支持悬停、键盘聚焦及触屏长按，长按不会执行动作；更多菜单包含流程设置、添加触发器、整理布局与导入导出。工作区展开与显示完整流程使用不同图标。

同一功能组中的 1–2 个图标按钮独立呈现，3 个及以上共用紧凑胶囊外壳。撤销与重做各有独立圆形材质；头部的保存、测试与次级操作权重不同，保持各自的圆形按钮，不共用外壳。缩放栏中的百分比是读数，不计入按钮数量；禁用不会改变分组，隐藏或移除动作则重新判断。窄屏保留紧凑分组并整组换行。

左下角按“缩小、当前比例、放大、显示完整流程”排列。比例来自实际视口，随按钮、手势与自动适配更新；数字等宽并与图标居中对齐，不占额外键盘停靠点。比例范围为 15%–180%。

工具栏采用单个 Tab 入口，内部使用左右方向键、Home/End 移动焦点。画布、节点和连线的右键菜单是快捷入口，配置栏、端点选择器和原工具栏仍能完成对应操作；菜单支持方向键、Home/End、Enter 与 Escape，关闭后返回原对象，转入配置或节点选择时把焦点交给新界面。聚焦节点后 Ctrl/⌘ D 复制；聚焦节点或连线后 Delete/Backspace 移除，文本输入不触发这些快捷操作。

宽屏配置栏占独立空间，画布按剩余宽度计算可见范围；窄屏配置移到画布下方。编辑与缩放工具栏定位于画布本身，不跟随下方配置区域移动。复制节点只复制定义并避让已有位置，不复制连线；删除节点同时移除关联连接，两者均可撤销。

连线的来源节点与输出端点作为一次明确选择，条件的“命中 / 未命中 / 失败”由用户指定，不因切换来源而自动猜测。重接排除原边后重新校验类型、重复、容量及无环约束，保留边标识；无效拖放保留原线。通过某条连线插入时只替换该边，保留并行节点的其他分支；新增并行分支从并行节点标题旁的分支图标进入。

### 从输出与连线继续编排

- 空画布的虚线节点是起步入口，不写入定义。只提供 `kind: trigger` 的模板；未提供触发模板或处于只读状态时显示真实空态。
- 输入与输出端点保留拖线能力。只有未连接输出显示短引线和圆形加号；输入及已连接输出不显示加号。已有连线在实际路径长度的中点显示一个插入加号，随节点移动与缩放保持在路径上。
- 两类加号共用视觉规范：悬停轻微放大，画布坐标下点击区域为 40×40px、可见圆为 12px、加号为 7px，随画布缩放。外围状态高亮为独立的 20px 圆，悬停、按下和展开都不填充整个点击区域；键盘轮廓围绕这个小圆显示。可放大画布或用键盘操作，减少动效时取消过渡。连接手柄维持 9×9px，普通端点为实心、失败端点为空心；细微渐变与内阴影提供层次，强制配色下保留实心/空心区别。
- “命中 / 未命中 / 失败”按连线的 `port` 显示为独立文字：中点处横线标在按钮上方，竖线标在右侧，避开按钮点击区。普通 `out` 不重复标“输出”；分支文字在只读时仍可见，不依赖悬停。
- 点击加号，或把连接拖到画布空白处，会打开同一个可搜索选择器。先选择再创建，关闭不会留下孤立节点。拖到不兼容节点不会触发新增。
- 空闲输出添加后续步骤；连线加号插入新步骤，同时替换该边、保留两端及原来源出口。需要选择新条件节点的后续出口时，以“命中 / 未命中”明确列出，不能代替业务选择。
- 并行 `out` 未连接时使用输出加号，连接后使用节点标题旁的“新增并行分支”图标。这个入口追加独立分支，连线上的加号只插入该分支的步骤。可连接的已有节点单独列于“连接已有”，可直接汇入已存在的汇合节点；插入只提供新节点。
- 输入端可拖线到空白处添加上游；汇合与异常处理的输入允许追加上游。直接拖线与就近选择器沿用同一套类型和连接约束。
- 候选项按方向、声明的数据类型、单入/单出、重复连接及无环约束过滤，提交时再次校验。失败出口按 `error` 类型检查；接收端需声明兼容类型或 `any`，不再把失败上下文当作普通观测。
- 新建与连线、插入与原边替换作为一次撤销步骤。新节点避让已有节点，已有位置保持不变；整理全图由用户明确操作。
- 菜单支持搜索、方向键、Home/End、Enter、Escape 和触控选择；Escape 返回入口。菜单按视口避让边缘，在展开工作区内仍可操作。
- “新增节点 / 连接已有”使用对应的 Tab 内容区域。标题、搜索和切换栏保持自然高度，长候选列表在独立区域滚动；未选中项悬停只轻调文字，选中状态仅由一个滑块表达。

只有提供 `onSave` 才显示保存；允许保存结构尚未完整的草稿，回调成功后才显示已保存，失败保留草稿。只有提供 `onRun` 才显示测试。运行接收一份定义快照、`AbortSignal` 和 `onUpdate`；更新必须来自同一次请求。编辑、外部更新或取消后，旧结果不能覆盖新流程。保存/运行期间禁止本地编辑与重复提交。`saveLabel` / `runLabel` 调整图标按钮的提示与无障碍名称。

`renderNodeConfiguration(node, { readOnly, onChange })` 允许宿主提供连接器选择、字段映射或表达式编辑等专门表单。宿主负责遵守只读状态、提供标签和业务校验；名称、执行策略、节点定义及统一的运行结果区仍由 Block 组织。不传时按 `parameters` 渲染基础表单。

事件监听、Cron 解析与调度、连接访问、授权、业务规则、算法/模型、持久化、队列、并发上限、超时、幂等、重试、结果回读和真实投递都由宿主服务实施。失败出口携带实际错误上下文。重试会带来重复投递可能，应用必须定义幂等键及具体策略。界面发出取消请求不等于后台已取消。

每份 `WorkflowRun` 必须携带 `workflowId` 和派发时的 `definitionSignature: workflowSignature(definition)`。后者是去掉节点布局位置后的序列化定义，用于界面关联，不是安全哈希。通过 `run` 传入的外部记录也必须匹配当前定义；修改参数后旧记录隐藏，单纯移动节点仍可保留记录。

`run` 是可选的受控运行记录：传入匹配当前定义的 `run` 时，它优先于组件内部回执。宿主同时使用 `run` 与 `onRun` 时，应把新运行及其进度同步写回 `run`；只使用 `onRun` 时由组件管理返回记录。

无需 Graphite 也可以使用已有的 shadcn 主题。局部布局与 React Flow 的基础 CSS 随 Block 安装；颜色、材质和圆角使用宿主主题变量。Graphite 的同一份来源继续用于展示页、安装与 Theme 导出。


## 运行结果的信息组织

- 标题下以三个一致的只读状态项呈现：发布状态使用图标与文字（Draft / Published / Unpublished changes / Unknown），节点数量使用图标与 n node(s)，校验使用图标与 n issue(s)。数量和发布状态从当前定义与宿主元信息推导，0 始终显示。图标统一为 14px、1.75px 线宽；文字使用次级信息色，语义色主要用于图标，多项问题整项使用红色。三项都支持悬停、键盘聚焦和触屏长按提示，点击不触发操作，也不显示按钮式反馈或打开问题抽屉；触控目标至少 40px，窄屏整项换行。测试前仍执行结构校验；有问题时提示原因，并定位到相关节点、连接或流程配置。并发上限仍在流程设置和并行节点摘要中。
- 底部只承担当前定义对应的一次执行。提供 `onRun` 或匹配的 `run` 才显示结果入口；没有执行接入时不放无效的“调试”按钮。运行自动展开，折叠保留真实状态与总耗时。总耗时由整次运行的开始与结束时间计算，不能累加并发节点耗时。
- 展开后显示节点导航和相邻的数据详情，选择节点不会再跳去配置栏。默认优先展示失败节点，其次为执行中节点，再次为最后完成的成功节点；选择记录后保持用户选择。失败筛选不隐藏错误详情。每行以状态图标、名称、耗时单行呈现；名称仅做视觉省略，提示及详情可读全文，触控选择后在详情核查。选中采用平面底色，不加左侧装饰线。定位画布、查看配置均为明确动作。
- 节点详情先显示状态、耗时、尝试次数与执行消息，输入 / 输出 / 执行信息分别核对原始载荷及 UTC 时间。数据中的 `0`、`false`、`null`、空字符串、空数组照实保留，未提供值单独显示。节点没有回执时表达为“未提供回执”，不能代填等待、跳过或成功。
- 运行详情提供运行标识和完整 UTC 起止时间；数据仅关联当前匹配定义，改变参数后不会显示旧结果。配置栏的“查看执行数据”和节点右键入口均进入同一个结果区。
- 请求失败显示真实错误；停止等待保留最后已收到的回执，说明后台取消尚未确认，不把所有节点强行改成已取消。
- 当前组件不提供执行历史、事件日志流、输入固定、失败重放或单步执行。这些能力需要宿主提供相应数据与执行接口；当前运行回执不能冒充历史调试服务。


`publication?: WorkflowPublication` 由宿主提供，与保存草稿回调独立：

```tsx
// 当前流程尚未发布。
publication={{ workflowId: workflow.id, status: "draft" }}
// definitionSignature 必须来自真正发布成功的定义。
publication={{
  workflowId: publishedWorkflow.id,
  status: "published",
  definitionSignature: workflowSignature(publishedWorkflow),
}}
```

未提供状态或记录属于其他流程时，显示灰色未知图标。当前定义与已发布签名相同时显示绿色已发布图标；参数等语义配置改变后显示草稿图标，提示有未发布更改；撤销回到已发布定义后恢复已发布。仅移动节点不会改变发布状态。保存成功仅更新保存入口的提示，不改变发布状态。展示页明确传入草稿；组件不自建发布服务。

## 节点的关键配置摘要

节点由类型与名称、关键配置摘要、运行结果三部分组成。类型来自 `kind`，名称来自 `label`；摘要用于判断节点正在做什么，不承载整份配置。`description` 是节点说明，不作为摘要的兜底内容。

宿主通过 `getNodeSummary(node, { workflow })` 返回 `WorkflowNodeSummary`。这是从当前配置计算的展示结果，不写回或另存到流程定义；更新参数、撤销、导入、切换流程时会重新计算。适配器按稳定的参数 `key` 取值，不能依赖参数数组的位置。

| 结构 | 适用场景 | 约束 |
| --- | --- | --- |
| `type: "fields"` | 数据源、触发器、聚合、模型、分发与执行策略 | 返回 1–3 条 `{ label, value, unit? }`，标签与值分列。选择能识别对象和关键行为的字段；完整参数仍在配置侧栏。 |
| `type: "expression"` | 能用一条比较关系概括的规则 | 返回 `{ subject, operator, value, unit? }`，分别提供比较对象、运算符、阈值和已知单位。表达式仅用于展示，不在浏览器求值。复杂规则可改用字段摘要，完整规则留在专门配置表单。 |

建议的内容选择如下；这是适配器的职责，不是组件对任意业务参数的猜测。

| 节点 | 摘要内容 |
| --- | --- |
| 事件 / 定时触发 | 事件类型与来源，或 Cron 与时区 |
| 数据源 | 连接与数据集；使用宿主提供的显示名称或实际引用，不展示凭据 |
| 质量校验 | 未通过时采用的处理策略 |
| 聚合 | 指标、方法、窗口；示例显示配置中固定区间的时长，精确起止时间在配置中核查 |
| 条件 | 比较对象、运算符与阈值；没有单位定义时不补造单位 |
| 并行 / 汇合 | 实际连接数量、全局并发上限 / 等待策略 |
| 分发 / 异常 | 目标或异常队列 |

例如，条件适配器从当前参数生成表达式：

```tsx
import type { DataWorkflowProps } from "@/components/blocks/data-workflow";

const getNodeSummary: DataWorkflowProps["getNodeSummary"] = (node) => {
  if (node.operation !== "compare-value") return undefined;
  const value = (key: string) =>
    node.parameters.find((field) => field.key === key)?.value ?? null;
  const operators: Record<string, string> = { gte: "≥", gt: ">", lt: "<" };
  const operator = operators[String(value("operator"))];
  if (!operator) return undefined;
  return {
    type: "expression",
    subject: "输入值",
    operator,
    value: value("threshold"),
  };
};
```

`0`、`false`、空文本、未配置和无效数值分别显示。只有调用方明确提供单位时才显示单位；选择项使用调用方定义的显示名称。摘要最多显示三项，长值在画布上省略，完整值保留于无障碍名称及配置侧栏。宿主的专门配置表单应能核查其摘要所引用的配置。

没有提供适配器摘要时，普通节点只显示真实参数数量，不擅自选取第一项、不拼接所有值，也不把描述当配置。并行和汇合的默认摘要由组件依据真实连线、`maxConcurrency` 与 `joinMode` 生成；并发上限不代表所有分支必然同时开始。运行状态与耗时独立显示，不混入配置摘要；缺少节点回执显示“未提供记录”。

节点宽度统一为 232px，内边距 12px，标题与摘要间距 10px，摘要条目间距 4px。标题最多两行，按实际行数占位；摘要只占实际条目所需高度。默认字号下，一行标题加一项摘要约 92px 高，两项约 114px，三项约 136px；两行标题、表达式和大字号按实际内容增长。没有摘要条目时不保留空摘要区域，只有存在本次运行记录时才增加结果行。

节点高度同时满足端点操作要求：同侧端点中心间距 42px，点击区域 40×40px，首尾各保留至少 4px。三个端点同侧时节点至少 132px 高，四个至少 174px；上下端点沿统一宽度排布。整理布局采用实际测量的节点高度，保留连线与端点操作空间；修改内容不会自动移动已有节点的位置。

## 并发与汇合语义

- 普通出口最多连接一个节点。并行分发的 `out` 可以连接多个独立分支，输入按分支分发；`maxConcurrency` 是单次运行的活跃节点上限，1 表示串行排队。
- 普通节点只有一个输入；多个输入通过 `join` 显式汇合。异常处理节点可接收多个失败出口。
- `joinMode: all` 等待全部输入成功；任一上游失败则汇合失败。上游被条件跳过时，汇合也跳过。条件互斥分支若需择一继续，应使用 `any`。
- `joinMode: any` 在首个成功输入到达且获得并发槽位后执行；其他分支继续运行，不自动取消。其他分支的失败仍保留在整个运行中。
- `condition` 必须分别连接 `true` 与 `false`。`error` 是失败流转，与正常结果和条件未命中分开。
- 运行状态包括 pending、running、succeeded、failed、skipped、cancelled。未开始的节点不伪造开始时间，未执行的结果不填零。

演示在本页内存中执行适配器，不订阅设备、不创建定时任务、不访问数据库、不调用 HTTP 服务，也不发送通知。所有观测均标注为演示数据，时间为 2026-11-12 00:00、00:10、00:20 UTC。
