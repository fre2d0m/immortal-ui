# 工作流节点内容密度修正

日期：2026-11-13。范围：节点内部布局、端点空间及整理布局；无提交或部署。

## 原因与结果

原实现为了等高，为所有节点固定预留两行标题、三行摘要，节点最低 168px。实际只有一行标题和一项摘要的归档节点，也被预留了约 20px 标题空行与 44px 摘要空行。截图中的底部空白没有承载信息或操作。

现在统一宽度、内边距、字号和对齐，高度取决于内容及端点的操作空间。字体与摘要字段未缩小或删减。

| 部分 | 原来 | 现在 |
| --- | --- | --- |
| 节点外壳 | 232px 宽、最低 168px 高、14px 内边距 | 232px 宽、12px 内边距，按内容占位 |
| 标题 | 强制预留两行名称 | 最多两行，按实际行数占位 |
| 摘要 | 固定三行高度 | 只呈现实际条目；空摘要不占区域 |
| 区域间距 | 标题至摘要 12px | 标题至摘要 10px，字段之间 4px |
| 一项摘要节点 | 168px | 约 92px，减少约 45% |
| 两项/三项摘要 | 均为 168px | 约 114px / 136px |
| 端点 | 统一 42px 中心间距 | 保留中心间距，按同侧端点数计算最低高度，40px 操作区与首尾 4px 空间不重叠 |
| 整理布局 | 测量高度小于 168px 时仍按 168px 安排 | 使用实际测量高度；未测量时保留原有估算 |

三端点同侧时最低 132px，四端点同侧时最低 174px。这部分高度服务于操作空间。长名称、大字号、表达式和已提供的运行结果按实际内容增长；未运行时没有结果占位。修改内容不自动移动已有节点，手动整理布局才重新安排位置。

## 验证

- 默认字号的 11 个真实演示节点逐项测量，记录于 `before.json`、`after.json`。
- 在实际组件中替换已知摘要为 0/1/2/3 项，确认每增加一项增加约 22px，内容对应输入；数值 0、false、空文本、null 分别正确表达。
- 深浅主题、20px 主字号、两行长名称、超长目标值。长值在节点中省略，完整值保留于可访问名称及键盘打开的配置中；未改变数据。
- 执行中、完成、失败、等待、跳过、取消六种已提供回执：出现独立结果行；移除回执后恢复原高度。
- 在摘要、标题与运行记录导致高度变化后，实际 SVG 连线终点保持贴合目标端点边缘。
- 三/四个端点同侧：中心间距 42px，40×40px 点击区域互不重叠，最低高度满足首尾空间。
- 手动整理布局采用实际节点高度。端点选择器正确添加 join → failure 的 error 连接；模拟执行结果仍为三条观测的均值 20°C，常规归档完成、复核分支跳过。
- 320px 窄屏和 20px 字号无整页横向溢出，键盘可打开完整目标配置。Chrome 触控模拟能点击紧凑节点的端点并选择下一步。
- 全新临时消费项目通过 shadcn CLI 安装 Graphite 和 data-workflow；四个 Block 文件与源码一致。深浅主题实际节点均约 232×92px，配置编辑更新宿主数据，端点入口仍可操作。
- `npm run check` 通过：类型检查、80 项测试、生产构建。独立消费项目类型检查及构建通过。构建保留大 chunk 提示。
- 本次最终浏览器检查没有页面、控制台或 HTTP 错误；两份临时服务日志未出现 ResizeObserver 警告。
- registry 与站点生成产物同步；`docs/` 与 `dist/` 一致，旧 docs 副本在 `/tmp/immortal-node-density/docs-before-sync`。`git diff --check` 通过。
