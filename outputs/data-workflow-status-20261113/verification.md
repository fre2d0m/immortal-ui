## 状态契约

- 发布状态与权限、草稿保存、运行状态互相独立。`publication` 为空或记录属于另一流程时显示未知图标，不能从只读或保存成功推断已发布。
- 已发布定义与当前定义一致时为绿色已发布；修改配置后为草稿，提示有未发布更改；撤销回原定义恢复已发布。位置不参与已有的 `workflowSignature`，拖动节点不改变发布状态。
- 展示页明确提供草稿元信息，没有发布服务；验收页的“模拟宿主发布回执”只用于测试受控数据变化，不属于可安装组件。
- 节点数量从当前定义计算，问题数量沿用当前结构及参数校验。节点执行状态和耗时仍来自运行回执，未知回执使用问号图标与完整提示。

## 实际验证

- `npm run check` 通过：类型检查、84 项测试、构建。新增两项测试覆盖发布来源、位置变化、配置修改和恢复；保存与发布的独立性由浏览器检查验证。最后颜色与样式变更另行构建通过；见 `check.log`、`build-final.log`。
- `check.mjs` 的 6 组 Chrome 检查通过：发布状态、保存、移动布局、配置修改与实际撤销、节点数量 0/11/12、校验 0/1/2/恢复、两种主题的对比度、单行几何、长名称、窄屏 390px、大字号 20px、触控和失败状态。
- 所有状态数字对比度达到 4.5:1；本次测得最低约 5.39:1。状态图标同时使用不同形状和提示，不仅依靠颜色。
- 各行状态、名称和耗时的垂直中心一致，耗时右边缘一致；普通指针行高 32px，触控至少 40px。单一选中项没有 box-shadow 或左边框，悬停另一行不会形成第二个选中项。
- 通过本地 registry 安装到独立消费者，三个 UI 文件与源文件逐字相同，model 保留完整发布类型与推导函数。独立 TypeScript 与 Vite 构建通过；安装版再次完成 6 组浏览器检查，额外核对提示保持打开时从 11 动态更新到 12。见 `installed/checks.json`。
- 实际展示页 `http://127.0.0.1:4177/#/blocks/data-workflow` 核对草稿/11/0，并运行得到已知聚合值 20°C，列表为 32px。见 `showcase-checks.json`、`showcase-header.png`、`showcase-results.png`。
